# Тестове завдання для Frontend Engineer

## Опис завдання

Необхідно створити **веб-застосунок для управління сільськогосподарськими полями** з можливістю відображення їх на карті, додавання моніторингових точок та базового керування.

## Функціональні вимоги

### 1. Карта з полями

- Відображення інтерактивної карти (Leaflet)
- Візуалізація 3-5 попередньо заданих полів у форматі GeoJSON
- Можливість перемикання між полями (список або клік на карті)
- Виділення активного поля іншим кольором
- Відображення базової інформації про поле (назва, площа)

### 2. Моніторингові точки

- Додавання точок на карті в межах вибраного поля (клік на карті)
- Кожна точка має містити:
  - Координати (latitude, longitude) WGS 84 (без висоти)
    - Додаткове виведення координат у MGRS системі. Обчислення на фронтенді.
  - Тип точки (випадаючий список: "Проба ґрунту", "Шкідники", "Хвороби рослин", "Інше")
  - Опис (текстове поле, опціонально)
  - Дата створення (автоматично)
- Відображення точок на карті з різними іконками залежно від типу
- Видалення точок

### 3. Панель управління

- Список усіх доданих точок з можливістю:
  - Фільтрації за типом
  - Пошуку за описом
  - Сортування за датою

### 4. UI/UX вимоги

- Адаптивний дизайн (desktop + tablet)
- Зручна навігація між полями
- Чітка візуальна ієрархія

## Технічні вимоги

### Обов'язкові технології:

- **React 18+** з **TypeScript**
- **Leaflet** для карт
- **State management**: Zustand або Redux Toolkit або Context API
- **Vite** як build tool
- **Tailwind CSS** для стилізації

## Важливі примітки

- Використовуйте mock дані (не потрібен backend)
- Зосередьтеся на якості коду та UX, а не на кількості функцій
- Покажіть свій підхід до вирішення проблем
- Код має бути готовий до code review

## Використання AI інструментів

**Ви можете використовувати інструменти штучного інтелекту** (ChatGPT, Claude, Copilot, тощо) для допомоги у виконанні завдання.

**Проте важливо розуміти:**

- AI - це інструмент, як Stack Overflow чи документація
- Весь код, який ви здаєте, має бути **повністю переглянутий та перевірений вами**
- Ви здаєте код **від свого імені** і несете за нього повну відповідальність
- На презентації вас попросять **пояснити будь-яку частину коду** - ви маєте розуміти кожен рядок
- Якщо ви не можете пояснити, чому код написаний саме так - це негативний сигнал

**Що ми перевіряємо:**

- Чи розумієте ви архітектурні рішення у вашому коді?
- Чи можете пояснити, чому обрали саме такий підхід?
- Чи здатні обґрунтувати альтернативні варіанти?
- Чи можете швидко орієнтуватися у власному коді?

**Рекомендація:** Навіть якщо використовуєте AI, завжди:

1. Розберіться, як працює згенерований код
2. Адаптуйте його під свій стиль та вимоги
3. Переконайтеся, що можете пояснити кожне рішення
