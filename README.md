# Field Manager

Веб-застосунок для управління сільськогосподарськими полями: інтерактивна карта з полями (GeoJSON), моніторингові точки з координатами WGS84 і MGRS, панель зі списком полів, формою додавання точки і списком точок із фільтром, пошуком і сортуванням. Тестове завдання на позицію Frontend Engineer. Без бекенду — лише mock-дані.

## Запуск

```bash
npm install
npm run dev
```

Інші команди:

```bash
npm run typecheck    # tsc -b
npm run lint         # eslint .
npm run pretty       # prettier --write .
npm run pretty:check # prettier --check .
npm run build        # tsc -b && vite build
npm run preview      # vite preview (перегляд зібраного dist)
```

## Використані технології

- **Vite** — build tool.
- **React 19** (остання мажорна версія шаблону `react-ts`) + **TypeScript strict**, без `any`.
- **Leaflet** / **react-leaflet 5** (мажорна версія, сумісна за `peerDependencies` з React 19). Тайли — OpenStreetMap.
- **Tailwind CSS 4** для стилізації.
- **shadcn/ui** — компоненти (`Alert`, `AlertDialog`, `Card`, `Button`, `Select`, `Textarea`, `Label`, `Input`) генеруються CLI й живуть у репозиторії (`src/shared/components/ui`) як власний код, не як залежність. Іконки в UI — `lucide-react` (іде разом із shadcn).
- **Zustand** — по стору на фічу, `persist` для точок.
- `mgrs` — конвертація WGS84 → MGRS на фронтенді.
- `@turf/boolean-point-in-polygon` — перевірка, що точка всередині вибраного поля.
- **ESLint + Prettier** (з плагіном для Tailwind).

## Архітектурні рішення

- **Feature-based структура.** Фічі `map`, `fields`, `points` у `src/features`, спільний код у `src/shared`, композиція в `src/app`. Залежності односторонні: `app → features → shared`; фіча імпортує іншу лише через її `index.ts`, єдиний зв'язок — `points → fields`. Межі перевіряються на code review, лінтером не форсуються: 3 фічі й один дозволений зв'язок видно одразу. На більшому проєкті або в команді форсував би їх через `eslint-plugin-boundaries` чи `no-restricted-imports`.
- **Zustand: стор на фічу, лише первинний стан.** Похідні значення (вибране поле, видимі точки, чи показувати форму) рахуються в хуках і компонентах, підписки вузькі (`useStore(s => s.x)`). Стан фільтрів локальний (`useState`), бо потрібен лише списку.
- **Стор → контролер усередині карти замість ref на карту.** Сайдбар лише пише вибір у стор, а `FieldFitController` і `PointFocusController` усередині `MapContainer` читають його й викликають `fitBounds` / `flyTo`. Карті байдуже, хто змінив вибір.
- **Координати.** Домен працює з `{ lat, lng }`; перестановка в `[lng, lat]` (GeoJSON, turf) і `[lat, lng]` (Leaflet) — лише в `shared/lib/geo/geometry.ts`. MGRS — похідне значення, рахується під час рендеру (`toMgrs`, точність 1 м), не зберігається; якщо конвертація неможлива, UI показує «Не вдалося обчислити».
- **Додавання точки: чернетка → форма → точка.** Клік по невибраному полю лише вибирає його; клік усередині вибраного ставить чернетку (перевірка `isPointInPolygon`), поза ним — підказку. Форма показується, лише якщо чернетка належить вибраному полю.
- **Дані на межах.** `parseFields` — простий мапер: mock типізований і перевіряється компілятором, валідація знадобиться з реальним API. Точки з `localStorage` — `unknown`, тому `parsePersistedPoints` відкидає невалідні записи, щоб зіпсоване сховище не ламало рендер.
- **Обробка помилок.** Помилка тайлів — `Alert` поверх карти; два незалежні `ErrorBoundary` (карта і сайдбар) з кнопкою «Спробувати ще раз» — єдиний класовий компонент, бо хука для помилок рендеру в React немає; видалення точки — через `AlertDialog`, бо його не можна скасувати.
- **Безпека.** Текст користувача виводиться лише як React-текст, `dangerouslySetInnerHTML` немає. Маркери — `L.divIcon`, у HTML якого потрапляють лише наші константи (колір і літера типу).
- **Рендеринг.** Поля — `<Polygon>` з `pathOptions` замість `<GeoJSON>` (простий рестайлінг вибраного поля). `FieldPolygon` і `PointMarker` у `memo`, координати полігона в `useMemo`, щоб вибір поля чи чернетка не перемальовували всі шари.
- **Фільтрація — чиста функція** `filterPoints`: поле → тип → пошук в описі → сортування за датою. Вибране поле визначає межі списку, без вибору видно точки всіх полів.
- **Адаптив desktop + tablet.** Один лейаут від 768 px: сайдбар 320 px і карта; прокручується лише сайдбар (`h-dvh`, `overflow-hidden`). На тач-екранах контроли shadcn збільшено до 40 px одним правилом за `data-slot`, tooltip поля показується лише на пристроях з наведенням.
- **Без роутера і TanStack Query.** Застосунок одноекранний і без бекенду, ці інструменти не дали б цінності.

## Припущення

- **Одиниця виміру площі.** У прикладі з ТЗ `"area": 45.2` не має вказаної одиниці виміру. Вважаємо гектарами. Для поля з ТЗ (`field-1`) значення залишено без змін, хоча геометрично полігон займає ~78 га — приклад із завдання вважаємо ілюстративним. Для решти полів площу порахували через `@turf/area` і округлили до 0.1.
- **Точка належить полю**, в межах якого її створено (`fieldId`).
- **Фільтри впливають лише на список.** Карта завжди показує всі точки, щоб пошук у списку не ховав дані з карти.
- **Popup маркера** відкривається і закривається повторним кліком по маркеру — стандартна поведінка Leaflet.
- **Вибране поле не зберігається** між перезавантаженнями, на відміну від точок.
- **Телефонний лейаут (< 768 px) свідомо не робили** — у ТЗ є лише desktop і tablet.

## Що б я додав, якби мав більше часу

- **Великі обсяги геоданих:** canvas-рендер (`preferCanvas`, `CircleMarker`) і кластеризація маркерів, для тисяч об'єктів — WebGL (MapLibre GL, deck.gl).
- **Real-time:** оновлення точок через WebSocket (upsert за `id` у сторі) і валідація відповідей API на межі (`zod` у `parseFields`).
- **Власний або офлайн тайл-сервер** замість публічного OpenStreetMap.
- Юніт-тести чистої логіки (`filterPoints`, `parsePersistedPoints`, `shared/lib/geo`).
- Редагування точок.
- Дебаунс пошуку (зараз фільтрація на кожен символ, для десятків точок цього досить).
- Лейаут для телефона і сайдбар, що згортається (у портретному планшеті карта займає лише 448 px).
- Синхронізація фокусу точки в обидва боки: клік по маркеру підсвічує картку в списку.
- Збереження вибраного поля між перезавантаженнями, версіонування формату точок у `localStorage`.
